# 配置指南

给应用管理员和服务维护者阅读。[文档导航](README.md)

## 首次配置顺序

1. **用户**：登记人员、角色、活跃状态与管理权限。
2. **模型**：由管理员选择共享模型、思考级别、Codemode 并保存 API Key。
3. **仓库**：登记仓库地址、名称与分组。
4. **服务**：关联仓库，为正式／测试环境设置基线和查询目标。
5. **凭证**：为实际处理工单的人准备所需的模型、SSH、DMS 或 SLS 凭证。
6. **验证**：用一张明确范围的测试工单验证，不把“保存成功”当作连接测试通过。

## 配置放在哪里

| 内容 | 保存位置 |
| --- | --- |
| 端口、数据路径、时区、硬限制 | 根 `issue-pilot.config.ts`，修改后按范围重启／重建 |
| 用户、服务、仓库、凭证、模型选择、参数 | SQLite，通过页面或 API 保存 |
| 模型目录、技能、扩展等 Pi 资源 | 应用运行用户的 `~/.pi/agent` |

不再使用用户／服务 YAML 导入导出，也不通过 `.env` 切换业务数据根。改配置文件里的初始用户不会修改已经存在的用户。

## 身份与权限

角色为产品、测试、开发者；**管理员是独立权限**。开发者不自动成为管理员，管理员也不自动获得开发处理权限。用户操作会保护必要的活跃用户和管理能力。

页面账号选择不是登录。应用没有自带登录认证或逐工单访问控制；开放到不可信网络前，必须由可信网关保护网页、API、下载、SSE 和 MCP。

## 模型与个人凭证

工单的凭证所属用户是**处理人，否则报告人**，并且必须活跃。

| 凭证 | 选择方式 |
| --- | --- |
| 模型 | 有完整个人模型组时整组使用个人设置，否则使用共享组 |
| Git SSH | 开发者本人私钥；不借用其他用户、宿主 ssh-agent 或共享身份 |
| DMS / SLS | 完整个人组优先，否则共享组；个人组残缺会报错 |

凭证缺失或失效不会自动换身份重试。原生查询的凭证不能增加服务或查询目标权限。

在“我的凭证”维护个人设置；共享凭证仅管理员可管理。保存表单时未改的秘密由页面保留；直接调用 API 不能把空字符串当作“保留原值”。

共享模型适用于所有服务和环境，不在每个部署上重复选择。宿主用户的 Pi 登录不替代应用数据库中的模型密钥。

## 服务与查询目标

- 服务关联仓库；正式／测试部署配置各自的基线和查询目标。
- 开发基线从**同服务的正式部署**推导，不另设一套开发基线。
- DMS 配置实例别名和数据库；实际连接信息由所选凭证解析。
- SLS 配置地域、项目和日志库；调用仍需指定具体日志库。
- DBHub 和外部 MCP 按部署归属管理；MySQL 使用配置的外部 MCP，不是原生 MySQL 查询器。
- 开发工单查询正式／测试证据时，需要明确选环境。

保存凭证不代表目标已配置，保存目标也不代表凭证或权限有效。配置更新被运行工单阻止时，先等待或中断任务，不绕过冲突检查。

## 参数与工单网络

“配置 → 参数”管理并发、模型等待、查询超时、代码保留期、容量阈值和网络策略。页面显示的有效值为准，不必改源码。

- 调低并发不会取消已经运行的工单。
- 超时通常针对等待或单次调用，不是保证整轮在该时间内结束。
- 自动回收只释放符合条件的开发代码，不删除会话、附件或工作文件。
- `open` 允许沙箱支持的出站访问；`allowlist` 只允许配置的域名。二者都不解除文件隔离或宿主控制地址限制。
- 保存新网络规则不强行切断已经建立的连接。

API 的参数更新是带版本的完整覆盖，接入方应阅读[配置契约](ai/CONFIGURATION.md#runtime-parameters)，不要只发改动的一项而意外清空其他覆盖。

## MCP 与钉钉

“端点”提供工单 MCP 客户端配置，地址为 `/mcp`。服务 MCP 只在工单允许的部署和服务范围内提供给智能体。

钉钉导入使用选定的**全局 MCP 连接**。个人偏好只保存来源和字段映射，不保存网关密钥；导入连接不作为智能体工具。

页面导入默认指派当前用户并启动；同一钉钉记录重复导入返回已有工单，不重复启动或改派。手工工单只在所选服务和环境内按标题或外部编号匹配；有多个候选时需先人工核对。导入成功但连接关闭失败时，页面会保留工单编号并提示检查连接，不应因此再次创建。HTTP／MCP 接入的默认值见[接口契约](ai/HTTP.md#dingtalk-import)。

模型目录准备、凭证字段、参数单位和协议预算等细节见 [AI 配置参考](ai/CONFIGURATION.md)。

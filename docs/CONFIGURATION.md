# 配置指南

给应用管理员和服务维护者阅读。[文档导航](README.md)

## 首次配置顺序

1. **用户**：登记人员、角色、活跃状态与管理权限。
2. **模型**：由管理员选择共享模型、思考级别、Codemode 并保存 API Key。
3. **仓库**：登记仓库地址、名称与分组。
4. **服务**：关联仓库，为正式／测试环境设置基线和查询目标。
5. **凭证**：为实际处理工单的人准备所需的模型、SSH、DMS 或 SLS 凭证。
6. **验证**：用一张明确范围的测试工单验证，不把“保存成功”当作连接测试通过。

## 配置放在哪里

| 内容 | 保存位置 |
| --- | --- |
| 端口、数据路径、时区、硬限制 | 根 `issue-pilot.config.ts`，修改后按范围重启／重建 |
| 用户、服务、仓库、凭证、模型选择、参数 | SQLite，通过页面或 API 保存 |
| 模型目录、技能、扩展等 Pi 资源 | 应用运行用户的 `~/.pi/agent` |

业务数据根只由根配置决定，没有环境变量覆盖。改配置文件里的初始用户不会修改已经存在的用户。

## 身份与权限

角色为产品、测试、开发者；**管理员是独立权限**。开发者不自动成为管理员，管理员也不自动获得开发处理权限。用户操作会保护必要的活跃用户和管理能力。

页面账号选择不是登录。应用没有自带登录认证或逐工单访问控制；开放到不可信网络前，必须由可信网关保护网页、API、下载、SSE 和 MCP。

## 模型与个人凭证

工单的凭证所属用户是**处理人，否则报告人**，并且必须活跃。

| 凭证 | 选择方式 |
| --- | --- |
| 模型 | 有完整个人模型组时整组使用个人设置，否则使用共享组 |
| Git SSH | 开发者本人私钥；不借用其他用户、宿主 ssh-agent 或共享身份 |
| DMS / SLS | 完整个人组优先，否则共享组；个人组残缺会报错 |

凭证缺失或失效不会自动换身份重试。原生查询的凭证不能增加服务或查询目标权限。

在“我的凭证”维护个人设置；共享凭证仅管理员可管理。保存表单时未改的秘密由页面保留；直接调用 API 不能把空字符串当作“保留原值”。

共享模型适用于所有服务和环境，不在每个部署上重复选择。宿主用户的 Pi 登录不替代应用数据库中的模型密钥。

## 服务与查询目标

- 编辑服务只会保存已有部署；需要补环境时，先点相应的“添加部署”按钮，再配置分支并保存。只改服务说明不会新增部署。
- 仓库目录支持 HTTPS 和 SSH。服务包含开发环境部署时，关联仓库必须全部使用 SSH；保存服务或修改目录地址时会检查。仅分析的服务可保留 HTTPS，但开发者作为工单凭证所有者时仍只能使用本人 SSH 身份，HTTPS 会被明确拒绝。
- 服务关联仓库；正式／测试部署配置各自的基线和查询目标。
- 开发基线从**同服务的正式部署**推导，不另设一套开发基线。
- DMS 配置实例别名和数据库；实际连接信息由所选凭证解析。
- SLS 配置地域、项目和日志库；调用仍需指定具体日志库。
- DBHub 必须使用远端数据库只读账号。工具的 SQL 分类和驱动的只读保护不能代替远端授权。部署中填写目标，密码不回显；同一类型、主机、端口、数据库和用户名下留空保留原密码，目标变更需重填。应用按需生成 stdio 连接，不再保存第二份 MCP 配置。目前服务 MCP 工具只来自这类生成连接；手工添加的 HTTPS／SSE／stdio 连接都是全局连接，只供钉钉导入，不会成为智能体工具。MySQL 使用配置的外部 MCP，不是原生 MySQL 查询器。
- 开发工单查询正式／测试证据时，需要明确选环境。

保存凭证不代表目标已配置，保存目标也不代表凭证或权限有效。只修改正式环境的 DBHub 目标时，正式和开发工单能看到变化，运行中会阻止保存；仅运行测试工单不会阻止。修改服务名称、说明或仓库绑定则影响该服务部署的所有环境。遇到冲突先等待或中断相关任务，不绕过检查。

## 参数与工单网络

“配置 → 参数”管理并发、超时、工作区回收、工单网络访问、钉钉附件主机和工单搜索。各项统一用「保存参数」提交，无需重启。

- 调低并发不会取消已经运行的工单。
- 超时通常针对等待或单次调用，不是保证整轮在该时间内结束。
- 自动回收只释放符合条件的开发代码，不删除会话、附件或工作文件。
- `open` 允许沙箱支持的出站访问；`allowlist` 只允许配置的域名。二者都不解除文件隔离或宿主控制地址限制。
- 保存新网络规则不强行切断已经建立的连接。
- 钉钉附件主机每行填一个主机名，导入只从列表中的 HTTPS 主机下载附件。

API 的参数更新是带版本的完整覆盖，接入方应阅读[配置契约](ai/CONFIGURATION.md#runtime-parameters)，不要只发改动的一项而意外清空其他覆盖。

Codemode 脚本由 Pi SDK 的进程级 worker 池统一调度，默认并发 2；宿主运行环境可通过 `PI_CODEMODE_MAX_WORKERS` 设置正整数容量，与页面上的工单并发分别生效。当前 SDK 排队上限为 60 秒，并计入脚本自身的超时预算；排队失败或取消的脚本不会执行工具。等待上限没有公开配置项。每个 worker 的脚本堆上限为 256 MiB，增加容量前应评估整机内存和实际负载。

### 工单语义搜索

在「配置 → 参数 → 运行参数」中，将「工单搜索」选为「启用」，填写 Cloudflare Account ID 和具有 Workers AI Read 权限的 API Token，然后点击「保存参数」。未配置凭据时默认关闭。Token 只在后端保存，留空保留已存值；更换账号需填写新 Token。选为「关闭」后可清除已存 Token。

[Cloudflare Workers AI 免费额度](https://developers.cloudflare.com/workers-ai/platform/pricing/)为每个账号每天 10,000 Neurons，UTC 00:00 重置。只用免费额度请保持 Workers Free，超额时 Cloudflare 会拒绝请求；Workers Paid 超额会计费。

启用后，管理员显式更新索引。索引只发送工单标题和完整描述给 Cloudflare Workers AI，长文本分段处理。搜索时只发送输入的查询，在本机 libSQL 按每张工单最相关的片段排序。结果覆盖所有账户的开放和已解决工单，并显示当前处理人。在输入框和编辑器外按 `Alt+K`（macOS 上 `⌥K`）打开弹窗，按回车搜索。其他已打开的页面可刷新以获得开关状态。

更新索引走现有管理员 API。下面示例在应用主机通过受保护的本地监听执行；替换为管理员的工单系统账号。远程访问应使用现有的认证网关。命令不用 Cloudflare Token，服务端读取已保存的配置。

```bash
node --input-type=module - 'admin@example.com' <<'NODE'
const subject = process.argv[2];
let after;
do {
  const response = await fetch("http://127.0.0.1:3000/api/issue-search/refresh", {
    method: "POST",
    headers: { "Content-Type": "application/json", "X-Issue-Pilot-Subject": subject },
    body: JSON.stringify({ after }),
  });
  const page = await response.json();
  if (!response.ok) throw new Error(page.error ?? `HTTP ${response.status}`);
  console.log(`写入 ${page.indexed} 张工单，移除 ${page.removed} 张`);
  after = page.nextCursor;
} while (after);
NODE
```

新增、编辑或删除工单后按需重跑。升级后也需执行一次更新：旧索引中已经覆盖全文的工单可复用，之前被截断的工单在重新建立索引后才会命中。失败后可从头重跑，已写入且内容未变的工单不重复计算。保存配置本身不调用 Cloudflare，也不验证 Token；用受控工单先验证实际访问和检索质量。

## MCP 与钉钉

“端点”提供工单 MCP 客户端配置，地址为 `/mcp`。服务 MCP 只在工单允许的部署和服务范围内提供给智能体。

钉钉导入只使用选定的**全局 MCP 连接**（未绑定部署）；绑定到服务部署的连接无论名称如何都是该服务的智能体工具，不能用于导入。个人偏好只保存来源和字段映射，不保存网关密钥；全局连接不作为智能体工具。

全局连接没有页面编辑入口，由管理员调用接口维护（字段和返回值见[接口契约](ai/HTTP.md#global-mcp-connections)）。示例中的地址、身份和密钥均为占位符，真实密钥不要写进脚本或命令历史：

```bash
BASE=http://127.0.0.1:3000
ADMIN='X-Issue-Pilot-Subject: <管理员 subject>'
# 查看现有连接（不含密钥）
curl -s "$BASE/api/mcp-services" -H "$ADMIN"
# 新建名为 dingtalk 的 HTTPS 连接；Authorization 从文件读取，避免出现在命令行
curl -s -X POST "$BASE/api/mcp-services" -H "$ADMIN" -H 'Content-Type: application/json' \
  --data @dingtalk-mcp.json   # {"name":"dingtalk","transport":"streamable_http","url":"https://<网关地址>/mcp","enabled":true,"credentialUpdate":{"mode":"replace","values":{"authorization":"Bearer <令牌>"}}}
# 测试连接：成功返回工具列表；失败只返回稳定错误码；stdio 运维日志只记录连接名和标准错误字节数，不记录子进程输出
curl -s -X POST "$BASE/api/mcp-services/<id>/test" -H "$ADMIN"
```

修改用 `PATCH /api/mcp-services/<id>`（只改名称或开关时可用 `"credentialUpdate":{"mode":"preserve"}` 保留原密钥），删除用 `DELETE`。有工单运行时写入会被拒绝，等待或中断后重试。钉钉偏好中的连接名称需与这里的名称一致（默认 `dingtalk`）。

新建工单时，钉钉记录中的非空「提出人备注」会追加到工单描述。重复导入直接返回已有工单，不更新描述。

页面导入默认指派当前用户并启动；同一钉钉记录重复导入返回已有工单，不重复启动或改派。手工工单只在所选服务和环境内按标题或外部编号匹配；有多个候选时需先人工核对。导入成功但连接关闭失败时，页面会保留工单编号并提示检查连接，不应因此再次创建。HTTP／MCP 接入的默认值见[接口契约](ai/HTTP.md#dingtalk-import)。

模型目录准备、凭证字段、参数单位和协议预算等细节见 [AI 配置参考](ai/CONFIGURATION.md)。

## 第一轮：启动、恢复与并发收尾

### P2：只读运行视图的并行准备提前结束

- **位置**：`src/workspace/project.ts`，`IssueProjectManager.hydrateReadOnlyRuntime`。
- **证据与触发**：关联会话路径的祖先是普通文件，真实文件探测返回 ENOTDIR；此时将共享仓库准备挂起，旧实现已经返回失败。仓库随后也失败时，其错误不进入调用方的失败链。两个回归场景修复前均失败。
- **影响**：冷启动恢复、转换失败后的视图恢复可能释放控制权，而共享 Git 准备仍在运行，与回滚、后续操作或关闭重叠。
- **修复**：两项准备使用 `Promise.allSettled`，保持原并发，待全部结束后报告单一或聚合错误；不更新未完成视图的仓库记录。
- **取舍与验证**：失败响应要等待仍在执行的 Git 操作及其既有超时。测试覆盖单失败、双失败、无提前数据库写入，以及纠正目录后成功重试。

### P2：无法清除过期运行状态仍报告恢复已结束

- **位置**：`src/workspace/runtime.ts`，`prepareIssueRuntimeBatch`。
- **证据与触发**：准备失败后，清除 `runtimeReady` 的数据库异常被 `.catch(() => undefined)` 丢弃。注入状态写入失败时旧实现返回普通 blocked 结果；真实 SQLite trigger 拒绝更新时记录仍可保持 `true`。
- **影响**：启动继续提供服务，但数据库的运行可用性与准备结果不一致。
- **修复**：状态写回失败聚合原准备错误并使批次失败；p-map 使用 `stopOnError: false`，确保其他已启动及本批次任务收尾后再交给 API 回滚。
- **取舍与验证**：单工单准备失败仍可标记受阻；无法保存该事实则阻止启动。测试覆盖并发排空、原始双错误保留、真实数据库拒绝、解除拒绝后重试，以及既有时间戳幂等性。

### P2：启动失败丢弃资源关闭错误

- **位置**：`src/http/api.ts`，`buildApi`／`startApi`。
- **证据与触发**：组装失败同时 Engine／租约关闭失败、租约获取与释放双失败、TCP listen 与关闭双失败，三个新测试在旧实现上均丢失清理原因。
- **影响**：运维只看见首个错误，无法判断资源是否完整释放，启动和正常退出两份实现还容易发生顺序漂移。
- **修复**：同一个幂等关闭 Promise 依次停止维护、关闭 Engine、排空 scope 队列、关闭模型运行时／数据库／租约。组装与监听错误保留原失败及次级错误；监听失败移除信号处理器。
- **取舍与验证**：清理失败不会阻断其他 owner 的关闭尝试，不保证故障介质上的资源必定删除。测试验证每个已初始化 owner 仅关闭一次、关闭顺序、错误链、重启及 `/health`。

## 第二轮：外部附件导入与流资源

### P2：文件暂存尚未开始读取时下载流无人清理

- **位置**：`src/http/dingtalk-attachments.ts`；错误分类调用方 `src/http/dingtalk-routes.ts`。
- **证据与触发**：读取器原来在异步生成器内部创建；磁盘不足导致 mkdtemp／open 失败时，生成器没有开始运行，已收到的 HTTP 响应流取消次数为零。取消恰遇响应清理失败时，原错误被取消原因替换。三个初始回归场景在旧实现失败。
- **影响**：失败导入可能遗留下载连接；清理未完成却只报告超时，失去定位线索。
- **修复**：收到响应后即接管读取器，暂存、读取、大小检查和非成功 HTTP 状态共用取消／释放路径。相同读取错误引起的 cancel 拒绝不重复计为清理故障；独立清理失败保留原错误链。清理失败优先于取消分类，对外返回服务端失败，日志只保留稳定诊断。
- **取舍与验证**：下载失败仍清除已暂存附件，工单创建事务不变，不跟随重定向、不扩大允许主机。新增目录／文件创建失败、取消双失败、非成功 HTTP 状态双失败、HTTP 入口净化测试；保留截断、超量、重复导入、事务回滚及重试覆盖。

## 第三轮：Web 会话流一致性

### P2：跳过坏帧后继续显示不完整会话

- **位置**：`src/web/src/app/agent-stream.ts`，message 事件处理。
- **证据与触发**：回放或实时阶段注入不可解析 JSON；旧实现仅调用 onError，不关闭连接，后续 snapshot 仍能被接受。另一个既有测试加强了非法运行状态后的恢复检查，三个断言在旧实现失败。
- **影响**：丢失的消息不会自动补齐，部分回放可能被当作完整快照，页面投影与持久会话不同步。
- **修复**：沿用已有 recover 流程，作废旧 generation、关闭连接并重新回放；迟到帧和 snapshot 被忽略。
- **取舍与验证**：坏帧增加一次重连；持续不合法的持久事件仍需修正来源，本轮没有新增重连策略。测试覆盖 replay／live 两阶段、旧连接排除、完整新回放；相关 Web 聚焦测试 58 项通过。

## 第四轮：模型运行时的临时目录所有权

### P3：初始化清理失败后遗失目录引用

- **位置**：`src/agent/model-runtime.ts`，`createPiModelRuntime`。
- **证据与触发**：ModelRuntime.create 失败且首次 rm 返回 EACCES；旧实现先将 privateDirectory 清空，又吞掉 rm 错误，后续 close 不再尝试该目录。
- **影响**：私有生成目录残留，调用方无法获知清理失败；没有证据表明该场景向外部泄露凭证。
- **修复**：删除成功后才结束目录所有权，初始化双失败保留 cause；随后 close 可重新尝试这次未完成的清理。
- **取舍与验证**：保持并发关闭幂等和关闭后拒绝 load，不增加无限重试。新增失败与正常清理两种场景，验证目录实际存在／消失、关闭调用次数及重复关闭；模型与会话相关 23 项测试通过。

## 保留设计、限制与后续

普通配置 GET 的身份隔离疑点在核对统一脱敏投影后排除，没有为该疑点增加校验。也没有删除保护不同等待时点的授权检查，或把有独立语义的媒体事务、队列和协议关闭合并成通用层。

本轮改善是失败状态可信、并行工作可排空、资源归属明确以及会话自动恢复完整性；没有测量或声称吞吐、延迟或内存性能提升。

没有执行真实外部模型、DMS／SLS、生产 DingTalk、生产部署或完整容器验收；Web 使用 jsdom，未做真实浏览器布局／选区验收。SSH 端到端测试缺少 openssh-server 夹具时的 skip 不算通过。故障注入覆盖了已发现的边界，但不证明所有并发交错或第三方行为安全。

本轮无需要确认后才能实施的重大架构、公共接口或迁移方案。最小后续工作是用匹配环境补齐 SSH、真实浏览器及外部系统验收，并观察新失败诊断；无需继续扩大重构范围。若将来需要客户端消息幂等、跨进程任务调度或数据布局迁移，应另行确认方案。

## 消融结论

- 同一组新增导出用例在基线失败 4 个场景，候选通过；候选另外覆盖旧来源仍需显式 owner。前端新增失败／重试用例在基线失败 4 项，修复后通过。
- MySQL 清空目标的真实 SQLite 观测：2 SELECT + 1 DELETE → 1 DELETE，保留其他部署连接；这只证明该操作减少查询，不宣称全应用吞吐提高。
- 在独立候选副本暂时移除 DMS 凭证目标检查后，已有回归失败。该检查已恢复并保留，防止把旧 Authorization 带到新地址。没有把权限、队列等待后重检、完整凭证组、事务 rollback 或历史保留当作冗余校验删除。
- 原服务转换器没有消费旧文件服务定义的生产路径：准备脚本始终从 DB 生成 version 2，再调用转换器。删除转换遍历后，用真实 CLI 往返覆盖当前导出用途，不保留只证明删除实现存在的单元测试。

## 加载测量

线上只读单次冷加载，在 Chromium 模拟 80 ms 延迟、250,000 B/s 下载（约 2 Mbps）时：4173 开发入口首次可操作约 21.8 秒，3000 同版本构建入口约 2.1 秒。本机未限速 trace 记录开发入口约 5.7 MB／74 个已完成资源，构建入口约 0.84 MB／16 个，说明开发模块图是远程冷加载的实质成本。具体结果受缓存、带宽和电脑影响，不外推到所有请求。

独立 baseline／candidate 构建各重复 3 次：默认用户页触发的配置相关 API 从每次 9 个降为 2 个，不再预读私有服务描述。用户区就绪时间中位数在该合成场景中均约 530 ms，没有观察到显著差异；主要实际冷加载收益来自日常入口使用构建文件，按需挂载另减少隐藏页面的请求和渲染。

- 类型、构建和 git diff --check 通过。
- 后端 540 项：539 通过，1 项 OpenSSH fixture 环境跳过；前端 27 文件、219 项通过。

- 上述场景也通过独立 Vite preview 代理验证，API catalog／endpoints 与直接 API 响应一致。
- 依赖版本未变，pip check 通过；生产 audit 仍报告既有 SRT／node-forge／Zod 的 3 个 high 包项和既有固定 backport，未屏蔽告警。
- 已发布迁移、历史分支／路径、原始凭证和归档配置不改写。保留独立的离线用户／来源转换，以及多个共享凭证组、私有文件模式、输出冲突和所有权检查。

# Workspace 存储查询优化

基线 e45cb59。针对线上 334 个工单，首次只读测量 `/api/workspaces/stats` 约 2,041 ms，同时 `/health` 约 20 ms，说明不是主线程完全阻塞。原统计只缓存容量值，每次仍遍历符合条件的工作区、逐工单查询仓库、分别执行 branch 和 status；首页默认统计分类不是资源，却会提前请求存储统计。

[原始实验数据](../experiments/workspace-statistics.json)包含独立 24 个已解决开发工单的三次首次采样、五次重复查询和浏览器验证。以下事项整体处理：

1. 完成的统计快照复用原容量缓存的有效期和失效标记，上限 60 秒；并发进行中的扫描仍共用原 statsPromise，不新增任务服务或持久索引。
2. 提供 sampledAt 和显式 `refresh=true`，用户可以重新采样；页面显示采样时间，避免把缓存当成实时状态。
3. 仓库按一次查询分组后传入检查，避免逐工单 SQL。每工单 inspection queue、生命周期 queue 和仓库串行化仍保留。
4. Git 使用一次 `status --porcelain=v2 --branch --ignored=matching` 同时读取分支和变更；启用 no-optional-locks，查询不刷新索引。detached、错误分支、staged／untracked／ignored 仍阻止释放，错误语义不变。
5. 释放、重开、转换与范围迁移在共同 owner 的开始和结束失效缓存，覆盖“扫描进行中时又排入释放”的竞态。维护开始也失效缓存，结束写入新容量采样。
6. 首页不预读未访问的资源分类，首次访问资源才请求；短时间切回保留结果，显式刷新时保留原内容并标识 busy，失败可以原地重试。
7. 不把多个工单合并为一次 du：GNU du 会跨根去重硬链接，改变现有逐工单口径。继续按工单测量，容量总和及共享 Git 单列语义保持原样。
8. 统计的可释放标记不是删除许可。释放和自动维护仍在当前工单预约内执行新检查，不使用统计快照跳过 Git／布局／活动状态保护。

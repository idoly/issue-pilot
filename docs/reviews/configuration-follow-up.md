# 配置管理审查修复与清理

基于已发布的 f9f8727，在 `fix/configuration-draft-lifecycle` 完成三个已复现 P2 问题的修复及配置链路清理。实现提交 8de9879 已推送并于 2026-10-25 部署到现有主机服务。

## 修复

1. **弹窗异步结果串入新建草稿。** 关闭、新建、重新打开分别推进编辑代次，旧 MySQL 请求的成功／失败回调失效。关闭同时结束该弹窗的忙碌状态，避免成功保存后下一次编辑永久禁用。回归覆盖同身份取消后新建、迟到成功／失败、提交体不含旧连接与密码。
2. **仓库 URL 变更遗漏服务版本。** 仓库 owner 在原事务内同时递增所有关联服务的 revision。旧 URL 重新登记后，旧服务草稿仍返回 configuration_changed，不再恢复旧绑定。显示名修改不推进服务版本，原预约范围及工单历史保持原有规则。
3. **重新加载入口放错弹窗。** 入口移到服务编辑错误区域，删除确认弹窗移除无效分支。私有详情冲突期间继续禁止保存；显式重新加载后可按新版本保存。保存失败仍保留草稿。

## 清理及保留依据

- 删除旧独立能力弹窗遗留的 capability／initiallyExpanded 参数、自动添加能力 effect、专用渲染分支。仓库内唯一生产调用是当前服务编辑器，未传这些参数；静态检索和全量测试验证了调用范围。
- 能力列表直接使用 CAPABILITY_KEYS，移除仅包装 key 的对象数组。直接调用 Solid snapshot，删除纯转发克隆函数；仅文件内部使用的帮助函数和类型取消导出。
- 删除已无对应后端错误来源的 invalid_deployment_mcp_services、service_configuration_save_failed 映射，以及删除确认弹窗永远无法触发的版本重载分支。
- 当前服务／仓库／凭证响应的 revision 改为前端必填字段，移除缺失版本时跳过 MySQL 版本比较的旧响应兼容；测试夹具改用当前 DTO。
- archivedDevelopment 的重复复制从输入解析阶段移除，由保存事务的历史配置保留逻辑统一处理。回归验证其内容保持原样，且不进入公开配置。
- 显式离线转换器仍有 CLI、测试及恢复文档调用，保留其离线用途；公开写接口可选 expectedRevision 的协议未在本轮改变。已发布迁移和持久历史字段保持原样。本轮没有增加通用版本框架、弹窗管理层或新依赖。

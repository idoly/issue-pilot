1. **P2：压力回收提前停止、容量缓存低报。** [lifecycle.ts](../../src/workspace/lifecycle.ts) 原先成功释放代码后扣除整个工单根目录并把其缓存归零，附件、对话、工作文件及私有 Git 仍在磁盘上。临时数据库和两个真实 Git worktree 复现：第一个工单保留 4 MiB 工作文件，第二个有 3 MiB 可随代码释放的忽略文件，旧实现只释放第一个。现在复用释放步骤测得的剩余容量更新总量与缓存，并在获得预约后重新读取工单上下文。测试确认继续释放第二个、保留文件字节不变、缓存与新 manager 的独立扫描一致、重复维护幂等。普通代码释放复用已有测量；幂等释放或运行目录恢复后需要测量实际剩余目录。保留数据超过目标时，释放所有合格代码仍可能达不到目标。

## 33. 借鉴 LayerFS 的生命周期原则，完善释放与自动回收失败处理

本轮只吸收共享基线、显式释放、冲突拒绝和按归属统计的原则，保留普通工单目录、Git worktree、Pi 与 SRT；没有安装 LayerFS、增加 FUSE／容器执行层或自动文件快照。参考为 [LayerFS 工作区模型](https://github.com/Ephemeral-AI-Lab/layerfs/blob/main/docs/general/concepts.md) 与公开发行边界，不采用其存储实现。

### 未提交内容与临时文件所有权

开发 worktree 的 clean 检查此前使用普通 porcelain，真实 Git 回归复现 `.gitignore` 文件及目录仍被 worktree remove 删除。现在同时检查 ignored 状态；存在忽略内容时复用 `workspace_has_changes` 拒绝释放。直接移除、生命周期释放与跨服务移除共用同一 owner。确需删除的依赖缓存由使用者显式处理，不仅凭目录名称认定可再生。

SourceBrowser 保存代码时，独占临时名发生 EEXIST 后原 finally 会删除其他操作的文件；回归先复现临时证据丢失。改为独占 open 成功后才承担清理，写完关闭再 rename，成功发布后不再删除已经释放的临时名称。写入／清理同时失败保留两类原错误并报告 `source_save_cleanup_failed`，描述符仍关闭。新增碰撞、部分写入、清理失败、重试及 rename 后名称被另一操作复用的回归，旧源文件和异常证据均按阶段保留。

### 自动回收错误与恢复

单个候选的会话关闭、Git 或视图异常进入内部维护 failures，按工单保留原错误；继续处理其他候选。启动会记录候选失败并继续提供 API，周期报告器自身抛错也不阻止其他错误报告。整体状态列表或磁盘测量失败仍报错，不伪装为候选已处理。失败后重算该目录实际占用，覆盖代码已经释放、后续阶段失败的情况。

释放后的视图重建失败不再吞掉：记录 runtimeReady=false／lastError，并明确报告 `workspace_runtime_restore_failed`。检查与页面区分代码已释放、视图待恢复、视图恢复失败。下一轮先恢复已有释放记录的未完成视图，不依赖保留期或新的磁盘压力；预约内重新确认是 development_snapshot 才走恢复，不删除仍有 active checkout 的候选。同一轮只处理一次，不盲目重放 Git 或 Agent 操作。

真实 Git／数据库用例覆盖会话关闭失败、部分释放后视图失败、其余候选继续、独立磁盘重算一致、重新构造管理器后在关闭保留期／配额回收时仍能恢复视图，以及处于失败状态但未解决的工单继续保留。补充真实 buildApi 启动测试，确认候选回收失败仍返回 health 200 且 checkout 内容不变。

### 资源统计与验证

新增 sharedGitBytes，按路径 owner 的 gitRoot 测量共享 bare store／checkout，与 totalBytes 的工单目录范围分开；沿用现有统计缓存，不改变配额范围。页面将“当前占用”明确为“工单目录占用”，“容量上限”改为“回收触发线”，共享 Git 独立显示。容量回归原来把未登记的忽略文件当可删缓存，现改用已提交大文件验证配额回收，另用专属回归保护忽略成果。

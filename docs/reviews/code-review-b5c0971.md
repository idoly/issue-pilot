## 按合理变更成本进行设计复核

用户补充的设计标准是：业务规则归属清晰，共同知识只维护一处，真实变化在合理边界内完成，依赖清晰稳定，抽象有明确收益，以及后续理解、修改和验证成本可控。本轮据此复核累计补丁，没有新增缺陷计数。

### 已落实的调整

1. **MySQL 行读取统一归属**：查询和导出原先重复维护字段提取、同名列校验、空结果检查、行映射与流读取。现在由同文件的 `readRows` 维护一次，查询消费者收集内存结果，导出消费者负责 CSV/JSONL。异步消费者被等待，保留文件写入背压；同步消费者不额外等待。去掉原先只用于包装查询收集的 `streamedRows`，没有引入跨协议读取框架。
2. **导出格式跟随现有输入契约**：`MysqlOutput` 从 `CapabilityInputs["db"]["output"]` 推导，避免独立维护几份 CSV/JSONL 类型。格式分派使用穷尽检查，契约扩充时要求实现相应格式分支。

# 服务能力展示与 MCP 归属修正

本轮按用户最新确认的规则处理：**配置了就展示，没有配置就不展示**。没有按测试／正式环境名称禁用 DMS，也没有新增 DMS 环境校验。

- 服务“代码分支”表头移除“继承正式”，只保留仓库／开发／测试／正式；实际开发基线和只读行为保持原样。清理对应无用样式。
- MySQL 在产品编辑器中是可选择的能力，和 DMS／SLS 一起出现在“添加能力”。未选时不渲染目标表单，已有目标自动选中，可移除整项能力；底层依旧通过部署所属的 MySQL MCP 执行，不把 MySQL 重新塞进原生 DMS／SLS 执行注册表。
- 原先完整配置与私有说明把所有启用的 MCP 列到每个环境，并标记“MCP（全局）”。现在读取 owner 只选择当前 deployment_id 的连接，生成的 MySQL 仍直接显示目标参数，避免重复列一份内部连接名。
- workspace describe 使用同一连接选择规则；Agent 初始化只加载入口／已包含服务在当前允许来源环境中的部署所属连接。其他服务连接和无部署归属的历史全局连接不自动注入。历史条目不猜测归属，不删除或改写现有配置。
- 默认 dingtalk 和当前 user_preferences.source.mcp 指定的连接仅用于钉钉导入，不进入服务说明、workspace 返回的 MCP 列表或 Pi 工具配置。钉钉导入 owner 自己的选择逻辑保持原样。
- 服务 DMS／SLS 部分仍读取实际部署 config。测试部署若确实配置了 DMS，仍会展示并可构造合法查询；未配置的 SLS 没有描述区块也没有查询工具。截图里的“添加能力”选项不等于已经配置。

实现沿用现有 mcp_services.deployment_id，不新增数据库迁移、运行框架、通用授权引擎或按环境禁用表。连接变更仍保留现有保守预约范围，未在本轮同时缩小并发边界。通用 MCP API 与历史连接数据继续保留；当前无归属条目不作为所有服务的默认连接。

验证：类型检查通过；前端 27 文件、224 项通过，构建通过。HTTP 及引擎回归覆盖部署归属、另一服务连接不泄漏、无归属全局连接不泄漏、默认／自定义钉钉连接排除、Agent 仍获得有归属连接、测试 DMS 根据配置可用及未配置能力不产生工具。完整后端 524 项：523 通过、1 项 OpenSSH fixture 环境跳过、0 失败。

## 发布与备份策略

发布前发现 Agent 活动时暂停停服，复查空闲后再重启。用户随后明确要求普通发布不重复创建完整一致快照，本次已停止正在进行的备份任务，未完成副本不作为恢复点，完成后清理。两份既有完整状态恢复点保持原样；本次只保留匹配源码、旧构建产物及必要的小型验证记录。无 schema、新数据迁移、配置清理或 Git／文件布局迁移。

Runbook 已按风险区分普通代码发布、小范围数据库操作和高风险迁移：普通重启／代码发布无需全量状态复制；有 schema、持久布局或跨媒体不可逆变更时才要求停写一致备份和独立演练。

线上 1440／390 只读验收通过按配置展示、无全局 MCP 重复、简化分支表头、MySQL 添加／移除及取消。无业务写入、pageerror 或横向溢出。SQLite integrity 为 ok、FK 为 0；用户、凭证、偏好、MCP、服务部署、附件和会话数据保持一致，开发工单仓库历史未变；正常启动更新了 18 条只读快照的 commit_before／updated_at，未将其错误描述为所有表绝对不变。

数据库表退役审计尚未实施删除。已完成的仅是上一轮两条重复旧 MySQL MCP 的 API 清理，本次没有 DROP TABLE 或删除历史配置字段。

# 使用指南

[文档导航](README.md) · [配置](CONFIGURATION.md) · [接口](HTTP.md)

本文面向报告人、处理人和开发者。当前宿主机的访问方式见[部署](DEPLOYMENT.md#访问与认证)；尚无模型、仓库或服务的新安装先完成[首次本地运行](DEPLOYMENT.md#首次本地运行)。账号选择只选择业务身份，不代替认证。

## 提交一张可处理的工单

选择当前账号和入口服务，说明实际现象、预期、证据范围和验收条件，按需添加处理人、抄送、附件和关联工单。

| 处理方式 | workMode | 环境／类型／代码 |
| --- | --- | --- |
| 正式问题调查 | `production_analysis` | prod／smart_analysis／只读快照 |
| 测试问题调查 | `test_analysis` | test／smart_analysis／只读快照 |
| 开发缺陷修复 | `development_fix` | dev／defect_fix／独立 worktree |
| 开发功能开发 | `development_feature` | dev／feature_development／独立 worktree |

开发方式要求创建者和凭证 owner 都是活跃 developer。owner 是处理人，否则报告人；未分配工单的 owner 仍是报告人。页面创建后自动启动处理，创建成功不表示模型或代码准备已完成。

Service 是业务入口，可关联多个仓库；Deployment 保存该服务在某环境的基线与查询目标。工单必须匹配有效 Deployment，开发基线来自同服务正式部署。每张工单只有一个 Workspace 和持久根。规则来源：[业务契约](../src/domain/contracts.ts)、[Schema](../src/db/schema.ts)、[工单路由](../src/http/issue-routes.ts)。

“包含服务”扩展代码／部署工具范围，“关联工单”只引入另一工单的只读证据，不能互换。调整关联要求当前工单未解决、视图已准备，当前及相关工单都无 Agent 活动；成功变化会安排重新准备，不只是增加链接。接口完整替换规则见[关联工单](HTTP.md#替换关联工单)。

钉钉页面导入默认指派当前用户并启动；重复来源打开原工单，不重复启动或改派。HTTP 和 MCP 的启动默认值不同，见[导入接口](HTTP.md#钉钉导入)。

## 查找与当前账号

工单侧栏是当前账号作为处理人的队列，不包含仅作为报告人／抄送人的工单或未分配工单。搜索匹配该集合的编号、标题、服务和环境，不搜索描述。置顶影响个人分组显示，`p0` 至 `p3` 是业务标签，两者都不改变 Agent 调度。

首页团队动态可打开其他人的未解决工单，当前实现会尝试切换到该工单处理人；关联卡片或已有链接打开时保留当前账号。打开后核对身份，切换账号会丢弃旧身份未发送的草稿。依据：[IssueQueue](../src/web/src/app/IssueQueue.tsx)、[App](../src/web/src/app/App.tsx)。

## 状态与完成条件

| 状态维度 | 含义 |
| --- | --- |
| 工单 status | open 待处理；in_progress Agent 处理中；pending 本轮结束等待确认；resolved 人工确认解决 |
| Agent runState | idle 无活动；queued 等待名额；running 已取得名额，包含准备和收尾 |
| agentRunning | 包含排队与执行，不只等于 runState=running |
| workspace.status | not_created／preparing／running／ready／stopped／failed，描述资源准备与运行，不代表业务结论 |

通常为 `open → in_progress → pending → resolved`。失败通常回到 open，记录 workspace.failed 和 lastError；pending 也不证明修复、测试或远程操作成功，必须阅读回复及证据。

人工状态操作只允许 pending → resolved，或 resolved → open。resolved 与非空 resolvedAt 等价；重开恢复合法本地代码，但不自动启动 Agent。活动、漂移或恢复失败会阻止转换，不直接改数据库绕过。依据：[状态路由](../src/http/issue-routes.ts)、[生命周期](../src/workspace/lifecycle.ts)、[流程测试](../tests/http/issue-api.test.ts)。

## 阅读与补充

正文流式显示为纯文本，完成后渲染 Markdown；思考直接显示，工具详情按需展开。工具卡片的“显示已截断”只是页面预算，不修改 JSONL，也不证明上游返回了完整结果。浏览历史时保留位置，使用“回到最新”查看新增内容；输入区与历史独立滚动。

输入框 Enter 发送、Shift+Enter 换行，可粘贴图片。排队或处理中显示 Esc 中断提示。在可见会话或输入框内按 Esc 取消当前及排队轮次；输入法组合、修饰键和长按重复不触发。取消等待准备检查点和工具信号响应，保留会话、用户消息及未发送草稿，不撤销已完成的文件修改或远程副作用。

Agent 草稿及发送失败按身份／工单保存在页面应用资源中，站内导航可恢复；刷新、关页签或切换身份会丢弃未发送内容。切换身份不撤销已发出的请求，迟到响应不能覆盖新身份输入。关闭网页或断开 SSE 也不等于取消服务端任务。

202 表示输入持久受理。运行中消息可能作为引导或下一轮排队；结果不明时先查会话和状态，不能自动重发。恢复、取消和未知结果契约集中在 [Agent](AGENT.md#消息接收与恢复)。

## 验证与费用

默认优先静态分析，不因缓存缺失例行安装依赖或完整构建。需要验证时说明目标，选择最小相关检查；回复必须区分未执行、临时夹具测试和真实集成。

页脚 `↑`／`↓` 是累计输入／输出 Token，`R`／`W` 是累计缓存读取／写入，`CH` 是最近主模型请求的缓存命中率。上下文显示当前占用估计及模型上限，auto 表示自动压缩；失败或中断保留上一次有效估计，已报告费用仍累计。

费用来源于 Pi 的供应商报告或目录估算，不等于最终账单。页脚路径截断时可悬停查看，模型旁显示思考级别；嵌套调用“记录不完整”不能视为全部成功。

## 检查文件与代码

附件原件只读，编辑时显式另存普通工作文件。脚本、报告及查询导出都在工作目录；粘贴图片属于 Pi 消息，不是工单附件。相关工单提供只读证据，重要结论核对源版本和时间。

调查代码只读；未解决的活动开发 worktree 可编辑、暂存和提交。只读代码及差异支持选择复制。编辑器保存比较读取时 SHA-256；外部修改导致 source_file_changed 时，先复制草稿、重新读取并合并，不能去掉冲突检查覆盖。

可编辑文件停止输入 500ms 后自动保存，也可 Ctrl/Cmd+S 或点保存。保存失败停止自动重试，显示文本不证明落盘。代码草稿属于当前编辑器，不能套用 Agent 草稿的站内保留规则。LF／CRLF 保留原换行，混合换行或独立 CR 在页面只读；变更列表刷新不自动替换编辑文本。依据：[CodeBrowser](../src/web/src/app/CodeBrowser.tsx)、[保存回归](../src/web/src/app/CodeBrowser.test.tsx)、[Source 接口](HTTP.md#源码读取与保存)。

## 范围、解决与重开

“变更处理范围”先展示预检，再确认执行；普通字段编辑不能更改范围。预检只说明配置差异，执行仍检查活动、凭证和工作区。

| 转换 | 约束 |
| --- | --- |
| 正式／测试调查切换或换服务 | 目标 Deployment 有效，只读重绑定 |
| 调查 → 开发缺陷修复 | 同服务，open／pending，workspace ready |
| 开发 → 另一服务开发 | 保持 type，open／pending，workspace ready |
| 修复 ↔ 功能；开发 → 调查；调查 → 开发功能 | 当前不支持 |

计划过期重新查看，不只替换 hash 自动确认。成功可安排 Agent，不代表模型完成。解决保留会话、附件、工作文件和持久分支；满足安全条件后只回收代码目录。重开不丢弃 dirty 文件，不从远端猜测历史。依据：[scope-transition.ts](../src/workspace/scope-transition.ts)、[接口](HTTP.md#范围转换)。

## 重置会话

开发者可在未解决、空闲工单中重置。新会话不自动运行，旧对话留在历史；代码、附件和工作文件保留。`issue_saved_session_reset_failed` 表示组合编辑已保存而重置失败，先重读详情及会话列表，只重试独立重置，不重复上传。

独立重置要求当前 expectedSessionId；响应不明先查 current 会话，不能无条件用新 ID 重试。重置不能修复缺失根或坏 JSONL，见[重置接口](HTTP.md#独立重置会话)。

## 设置与运营统计

配置分用户、仓库、服务、端点和参数。仓库分组独立保存，不由服务关系推导。角色与管理权限、个人／共享凭证及热参数见[配置说明](CONFIGURATION.md)。

首页“周期解决”按创建周期中当前已解决的工单计数，不按解决时间归档；同名用户按 subject 区分，未分配单独统计。资源统计带采样时间，回收候选占用不等于实际可释放量。

## 遇到问题

先查看工单状态、workspace.lastError 和对应会话；模型、Git、SRT、查询目标及凭证分别定位。不要反复新建、重发或重启。部署入口问题见[运维定位顺序](RUNBOOK.md#从启动到首张工单的定位顺序)，结果不明或部分成功见[接口错误约定](HTTP.md)。

# 使用指南

[文档导航](README.md) · [配置](CONFIGURATION.md)

## 提交一张可处理的工单

页面顶部选择当前账号，进入“工单”新建。写清实际现象、预期、证据范围和验收条件，选择入口服务及处理方式，按需添加处理人、抄送、附件和关联。

| 方式 | `workMode` | 环境／`type`／代码 |
| --- | --- | --- |
| 正式问题调查 | `production_analysis` | prod／smart_analysis／只读快照 |
| 测试问题调查 | `test_analysis` | test／smart_analysis／只读快照 |
| 开发缺陷修复 | `development_fix` | dev／defect_fix／工单私有分支 |
| 开发功能开发 | `development_feature` | dev／feature_development／工单私有分支 |

product／test 可使用调查方式；开发方式要求 developer。凭证 owner 是处理人，否则报告人，必须活跃。账号选择不是认证，生产环境由可信网关绑定身份。

页面创建后自动启动处理。顶部“钉钉”导入单条记录，新工单默认指派当前用户并启动；重复来源打开原工单，不重复启动或改派。入站 MCP 的默认行为另见[协议说明](CONFIGURATION.md#入站工单-mcp)。

### 服务、部署与关联

服务（Service）是工单的业务入口，可绑定多个仓库；部署（Deployment）是该服务在一个环境的基线与查询目标。仅登记仓库不等于已有可用服务，选择处理方式还要求对应 Deployment 存在。开发基线取同一服务的正式部署，不能另配一套 dev 基线。Workspace 是每张工单唯一的准备／运行记录及持久根，回收代码目录不删除工单。

“包含服务”扩展本工单的代码和部署工具范围；“关联工单”只提供另一工单的只读证据，两者不能互换。业务映射以 [contracts.ts](../src/domain/contracts.ts) 为准，记录关系见 [schema.ts](../src/db/schema.ts)，查询范围见 [Agent](AGENT.md#原生证据查询)。

### 查找工单与当前账号

工单侧栏是**当前账号作为处理人**的队列，不包含仅作为报告人／抄送人的工单或未分配工单。搜索在这个集合内匹配编号、标题、服务 key／名称和环境 key，不搜索描述。置顶仅影响个人列表的显示组，同组保留服务端创建时间顺序；不会改处理人或 Agent 执行优先级。

首页团队动态可打开其他人的未解决工单；当前实现会尝试将顶部账号切换为该工单处理人。通过关联卡片或已有工单链接打开则保留当前账号。打开后先核对账号；账号切换会清空旧身份的未发送 Agent 草稿。账号选择仍不代替生产认证。依据：[IssueQueue](../src/web/src/app/IssueQueue.tsx)、[首页打开逻辑](../src/web/src/app/App.tsx)、[交互回归](../src/web/src/app/App.test.tsx)。

## 状态与完成条件

工单业务状态、Agent 活动和代码准备状态是三件事，不能只看其中一个字段判断成功：

| 字段 | 值与语义 |
| --- | --- |
| `status` | `open` 待处理／执行失败后待处理；`in_progress` Agent 处理；`pending` 一轮处理结束，等待人确认；`resolved` 人工确认解决 |
| `agentRunning`／SSE `runState` | `agentRunning=true` 包含 `queued` 和 `running`；`idle` 只表示当前无排队／执行活动，不代表已解决 |
| `workspace.status` | `not_created`、`preparing`、`running`、`ready`、`stopped`、`failed`；表示准备、运行或代码回收状态，不是工单结论 |

通常流程为 `open → in_progress → pending → resolved`；补充消息／继续处理可使未解决工单再次进入处理。准备或执行失败通常回到 `open` 并记录 `workspace.status=failed`、`lastError`。`pending` 只是本轮完成，不是测试、修复或外部操作成功的证明，仍需阅读回复和证据。

手工状态接口只接受 `resolved`（当前必须为 `pending`）或 `open`（当前必须为 `resolved`）。解决时设置 `resolvedAt`，重开时清空；重开恢复所需代码但**不自动启动 Agent**，需再发送消息或继续处理。并发活动或恢复检查失败会拒绝转换，不能直接改数据库绕过。

规则依据：[业务契约](../src/domain/contracts.ts)、[状态路由](../src/http/issue-routes.ts)、[Engine](../src/agent/engine.ts)、[重开与回收](../src/workspace/lifecycle.ts)；流程回归见 [issue-api.test.ts](../tests/http/issue-api.test.ts)。

## 阅读与补充

[会话页面图](images/workspace.jpg) 展示了对话、工具、描述和文件的布局。

- 排队表示已受理、正在等待并发名额；不是模型已经执行。
- 流式正文和思考过程先显示纯文本，完成后渲染 Markdown；思考过程直接显示为灰色文本，不折叠。会话内容使用可用宽度，不再居中限制为固定窄栏；长正文和标识符自动换行，宽表格在自身内部横向滚动，不会撑宽整条消息或被右侧工单栏遮住。
- 工具卡片默认折叠，展开查看输出、diff、图片、耗时和可用的嵌套调用记录。
- 浏览历史时可点「回到最新」；有新条目时按钮显示数量。聚焦会话后也可按 Enter 回到底部，工具卡片保留自身键盘操作。
- 输入区固定在会话底部，可以点「发送」，或按 Enter 发送、Shift+Enter 换行；也可直接粘贴图片。长草稿在输入框内滚动。运行中消息按引导／排队语义受理，空闲时继续处理。
- 草稿、发送失败和图片属于应用资源中的具体工单，同一页面内导航后可恢复；它们只在内存中，刷新、关闭页签或切换身份会丢弃未发送内容。离页提示不是持久保存。切换身份不撤销已经发出的请求，迟到响应不会覆盖新身份输入。

消息发送的 202／accepted 表示输入持久保存，不表示模型成功完成。发送结果不明时先看对话、状态和文件，避免重复提交。没有客户端幂等 ID 或跨进程自动执行保证。关闭网页、切换工单或断开 SSE 都不等于中止服务端任务；当前 HTTP 路由没有面向用户的 Agent abort 接口，不要通过刷新或重启模拟安全撤销。

## 验证与费用

Agent 默认优先静态分析，不因缓存缺失自动安装依赖或完整构建。确实需要执行验证时，说明目标并选择最小相关检查；未执行的测试不能声称通过。

页脚费用来自 Pi，不是本应用重新计价。供应商报告、估算、来源未标明和混合来源用于说明记录来源，不等于最终账单。嵌套调用“记录不完整”也不能当作所有子调用都已成功。

## 检查文件与代码

附件原件只读，要求修改时显式另存普通工作文件。脚本、报告和查询导出从工作目录访问；超出预览预算可下载。粘贴图片属于消息，不进入附件库。

代码浏览器提供文件、差异、历史和定位。调查代码只读；活动开发 worktree 可编辑、暂存和提交。保存出现 `source_file_changed` 时先核对外部修改；CRLF 等编辑细节由页面处理，不盲目覆盖冲突。Agent 仅在明确授权后提交／推送，提交信息按应用指引使用简体中文。

可编辑文件默认在停止输入 500ms 后自动保存，也可用“保存文件”或 Ctrl/Cmd+S。观察“等待自动保存／保存中／已保存／保存失败”，不能以输入已显示判断落盘。保存失败后会停止自动重试；遇到哈希冲突先复制草稿，再重新读取并合并最新内容，未经合并的重复保存仍会冲突。重新读取可能放弃草稿，先检查确认提示。

源码草稿属于当前编辑器，不能套用 Agent 草稿的导航保留规则。LF／CRLF 文件保留原换行；混合换行或独立 CR 的文件在页面只读。“变更”列表定时刷新不自动替换正在编辑的文本，外部改文件后需重新读取。依据：[CodeBrowser](../src/web/src/app/CodeBrowser.tsx)、[保存与导航测试](../src/web/src/app/CodeBrowser.test.tsx)。客户端接入见 [Source API](HTTP.md#源码读取与保存)。

关联工单只读提供代码、文件和会话，不扩大查询范围。元信息在准备时生成，不是实时摘要；重要依据需核对源文件、版本和时点。

## 范围、解决与重开

变更服务或处理方式使用“变更处理范围”，先检查预检结果再确认。相关活动会阻止冲突操作，不通过普通字段编辑绕过范围转换。

| 转换 | 当前条件 |
| --- | --- |
| 正式／测试调查之间切换或换服务 | 目标有有效 Deployment；只读重绑定 |
| 调查 → 开发缺陷修复 | 同服务，工单 `open`／`pending`，workspace `ready` |
| 开发 → 另一服务的开发 | 保持原 `type`，工单 `open`／`pending`，workspace `ready` |
| 开发修复 ↔ 开发功能；开发 → 调查；调查 → 开发功能 | 当前不支持 |

同范围请求不产生转换。计划只说明配置差异，执行仍会检查活动、工作树和凭证；计划过期需重新查看，不自动覆盖。成功转换可安排后续 Agent，需继续观察完成状态。请求与返回见 [范围转换接口](HTTP.md#范围转换)，条件 owner 为 [scope-transition.ts](../src/workspace/scope-transition.ts)。

结果满足要求可确认解决，否则继续反馈。解决保留会话、附件、工作文件和持久分支；安全条件满足后可回收代码目录。重开从合法本地分支恢复，不丢弃 dirty 文件，不从远端猜测替代缺失历史。

## 重置会话

开发者在编辑工单中使用“重置”。组合操作先预检当前状态和会话，再在同一预约中保存字段／附件并创建新会话；旧对话留在“查看历史”，代码、附件和工作文件不删除，新会话不会自动执行。

运行中或已解决工单不能重置。若提示 `issue_saved_session_reset_failed`，字段／附件已保存但重置失败；先核对详情和会话列表，只重试重置，不重复上传附件。预检拒绝与提交后的失败边界见 [HTTP 约定](HTTP.md#工单创建与编辑)。

## 设置与运营统计

配置分为用户、仓库、服务、端点和参数。服务标签可横向滑动，不显示滚动条。添加／编辑按钮留在详情卡片外，窄屏时排到下一行。代码分支与服务描述分开显示，阅读长描述时只滚动描述正文。

仓库列表默认显示全部，可按已保存的分组筛选。登记或编辑仓库时选择已有分组、选「其他」，或选「新建分组」后输入名称。分组随仓库保存，不随地址变化。升级时现有仓库按旧列表的归类一次性填充分组，`xhgj-mall` 仍显示为 `mall`。列表可独立滚动，桌面表头保持可见，长名称、地址及服务名悬停可查看完整值。

人员列表独立滚动，凭证、搜索和添加入口留在列表外。端点的「可用工具」默认收起，展开不会带动页面，工具列表超出高度时在列表内显示细滚动条。参数单位和简短说明放在字段名称旁，表单可滚动但不显示滚动条，保存按钮留在标题行。

个人／共享凭证入口及权限见[配置指南](CONFIGURATION.md)，运行参数可热更新，但现有轮次不会一律立即重建。

首页固定在视口内，整页不会随滚轮、触屏或键盘滚动。团队工单动态和运营洞察的内容超出区域时可各自滚动；窄屏上的分布卡片和处理人统计可以横向滚动。

首页按创建周期统计产出、分布和团队。“周期解决”指该批创建工单当前已解决数量，不按解决时间归档。同名账号按 subject 区分，未分配单独计算。资源统计带采样时间，候选占用不等于实际释放量。

## 遇到问题

| 提示 | 建议 |
| --- | --- |
| 凭证缺失或失败 | 检查 owner 的所选个人／共享组，不期待自动换身份 |
| 配置版本冲突 | 保留输入，重新读取版本后保存 |
| 请求结果不明 | 查看工单与对话，不盲目重发 |
| 已保存但刷新失败 | 重试读取，不重复提交写入 |
| 会话／Git／工作区异常 | 保留错误码和现场，由维护者按[运维手册](RUNBOOK.md)处理 |

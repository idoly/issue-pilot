# 使用指南

给报告人、处理人和开发者阅读。[文档导航](README.md)

## 创建工单

1. 核对右上角的当前账号。
2. 选择入口服务和处理方式，填写标题、优先级、现象、预期和验收条件。
3. 按需选择处理人，添加附件、抄送和关联工单。
4. 创建后等待处理，查看对话中的进度与结果。

| 处理方式 | 代码权限 |
| --- | --- |
| 正式问题调查 | 正式环境只读代码 |
| 测试问题调查 | 测试环境只读代码 |
| 开发缺陷修复 | 开发环境独立工作区 |
| 开发功能开发 | 开发环境独立工作区 |

开发工单要求创建者和实际处理身份均为开发者。没有处理人时，使用报告人的凭证；它不在任何人的“分配给我”范围内，可在“我报告的”“抄送我的”或“全部”中找到。创建成功只表示保存并安排处理，不表示 AI 已完成。

建议描述：“什么时候、在哪个服务出现什么问题；期望是什么；允许查询或修改什么；怎样算通过”。不要粘贴连接密钥。

## 查找工单

- 侧栏范围可选“分配给我”（默认）、“我报告的”、“抄送我的”和“全部”，都相对当前账号。切换到首页或配置再回来时保留所选范围，刷新页面后恢复默认。只有分配给自己的工单可以固定。
- 可搜索编号、标题、服务和环境；不搜索描述正文。
- 启用[工单语义搜索](CONFIGURATION.md#工单语义搜索)后，按 `Alt+K`（macOS：`⌥K`）可搜索所有账号的工单。输入后按 `Enter` 搜索，再用 `↑` / `↓` 浏览结果、按 `Enter` 打开选中的工单，或按 `Esc` 关闭弹窗。打开结果会清空侧栏筛选，选中工单并将它滚到侧栏可视区域顶部。
- 置顶和优先级只影响业务展示，不改变 AI 调度顺序。
- 从首页、语义搜索、关联工单、钉钉导入结果或链接打开工单**不会切换账号**：当前范围已包含该工单时保持不变，否则依次改为“分配给我”“我报告的”“抄送我的”中包含它的范围，都不包含时改为“全部”。后续编辑、消息和范围转换仍记在当前账号名下。

## 状态与完成条件

未解决工单正在执行或执行失败时，队列、详情和首页优先显示执行状态。

| 页面状态 | 你该做什么 |
| --- | --- |
| 执行中／环境准备中 | 等待本轮处理或环境准备完成 |
| 执行失败 | 阅读失败提示，必要时补充信息后点“重试处理” |
| 待处理 | 等待排队或继续处理 |
| 处理中 | 查看进度，必要时补充信息 |
| 待确认 | 阅读结论、证据和测试结果，决定是否解决 |
| 已解决 | 本次处理结束；有新问题可重开 |

“待确认”不等于修复或测试成功。人工确认解决只适用于待确认工单；已解决工单可以重开，但重开不会自动运行 AI。

## 阅读与补充

- **Enter** 发送，**Shift+Enter** 换行；可粘贴图片。
- 工具卡片可展开查看。标记“显示已截断”表示页面只显示部分正文，原始会话仍保留；上游结果是否完整要看工具说明。
- SLS 的完整查询结果可切换表格／原文，每页 50 条。Codemode 内的新查询也有独立“子查询”卡片，重连和历史回放可查看；旧会话中未保存的子查询结果无法补回。非表格或超过 32 列的结果保留原文。
- 查询卡片显示截断时，可点击“查看完整结果”，从原会话读取本次已保存的结果（最多 1 MiB）。读取、筛选、排序和翻页都不重新查询或增加模型费用；关闭卡片会释放完整结果，下次展开需重新读取。
- DMS 按服务端返回的文本表格展示，可切换原文。它不提供可靠的列类型，暂不支持 SLS 的本地排序、筛选和逐字段复制；较长的 DMS 响应保留原文。
- 点击表头依次切换升序、降序和原始顺序；数字列按数值排序，缺失字段和 null 始终在末尾。“复制筛选结果”按当前顺序复制所有匹配页的 JSON。长字段仅在表格中缩略，点击每行“查看”可阅读全文、复制单个字段或整条记录；复制失败会明确提示。
- 在历史位置阅读时不会自动拉回底部，点击“回到最新”查看新增内容。
- 处理中可在会话或输入框按 **Esc** 中断；弹窗打开时 **Esc** 由弹窗处理，不中断 Agent。中断需要等待收尾，不撤销已发生的修改或远程操作。
- 关闭网页不等于停止任务；断线会自动重连。
- 提交后的原消息与下一条草稿分别保留，发送期间可以继续输入；站内导航不丢失这些内容。发送结果不明时可点“查询接收状态”，不会自动重发。原消息可移入空草稿或移除记录；刷新、关页签或切换账号会丢弃本地内容。

## 文件与代码

附件原件只读。需要编辑时，让 AI 另存为工作文件；脚本、报告和查询导出也在工作文件中。粘贴到对话的图片不是工单附件。

开发工单推送提示 `fetch first` 时，可让 Agent「同步当前工单同名分支」。仅落后且工作区干净时会快进；有本地修改就保留。分叉时先看本地和远端各有哪些提交，再明确要求「合并刚核对的两端」。合并不会自动提交；冲突在工单内解决、暂存并复核，然后按授权普通推送，不变基、不强推。

调查代码只读；活动开发工单可按权限编辑、暂存和提交。可编辑文件停止输入约 500ms 后自动保存，也可按 Ctrl/Cmd+S。保存冲突时先保留草稿、重新读取并合并，不能强行覆盖。代码编辑草稿与对话输入草稿不是同一套保留机制。

Agent 按工作模式采用不同方法：调查工单从现象入口追到代码链路，区分已验证与推断；缺陷修复要求根因能解释全部现象，并检查调用方、接口约定、错误路径和并发边界；功能开发先写清行为约定再找现有模式扩展。复杂问题会先给出简短计划。修改后 Agent 会专门审查完整差异、新增文件和相关调用，修复确认的问题，并在会话中说明审查范围、实际验证及剩余风险。验证按代价从低到高进行：读代码、无需装依赖的语法检查（如 node --check、python3 -m py_compile、javac）、依赖已存在时的项目类型检查（tsc --noEmit、mvn -o compile），再到针对性测试；Agent 需要说明实际跑了哪些、跳过了哪些。只有你明确要求时才提交或推送：提交前复核实际暂存内容，推送前核对所有待推送提交；后续修改需要重审受影响部分。未解决的 P0/P1 问题会阻止 Agent 按此流程提交或推送。这是 Agent 的工作约定，尚非 Git 工具强制执行的审批门禁。

关联工单只提供只读证据；“包含服务”才会扩展允许处理的服务范围，两者不要混用。已解决工单不能修改关联；工作区尚未准备完成或正在处理时，“编辑关联”不可用。新建工单和编辑关联的候选列表与侧栏使用同一份工单列表，打开弹窗时刷新。

## 范围、解决与重开

修改服务或处理方式请使用“变更处理范围”：先看预检，再确认。不是所有转换都支持，页面拒绝时不要直接改数据库或目录。

当前支持调查之间切换、同服务调查转开发修复，以及保持类型的开发跨服务转换；不支持修复与功能互转、开发转调查或调查直接转功能开发。调查工单在任何状态（包括已解决）都可改到另一调查范围；转开发或开发跨服务要求工单待处理或待确认且工作区就绪。工单正在处理时不能变更范围。

解决后保留会话、附件和工作文件；系统只会在安全条件满足时回收开发代码。重开失败或发现目录异常时，联系维护者，不手工重建空目录。

## 重置会话

开发者可在未解决、空闲工单中重置会话。重置保留代码和文件，旧对话可从工单详情的“查看历史”读取（解决后仍可查看），新会话不会自动运行，也不会自动带入旧聊天。

编辑时若提示“工单已被修改”，草稿和待上传附件仍保留。先复制需要保留的内容，再点“重新载入（放弃草稿）”合并修改；读取失败不会清空草稿。

编辑并重置会话时，工单字段和会话绑定一起提交；重置失败会撤销本次编辑。若提示保存已完成但清理或刷新失败，使用“重新读取”检查结果，避免重复上传附件。

## 验证与费用

提出验证需求时说明要检查什么，例如“只做静态分析”“运行相关单元测试”或“需要真实服务验收”。回复应区分未执行、模拟测试和真实集成；JDK 不匹配不应直接当作代码有错。

页脚显示模型、用量、缓存、上下文和费用信息。费用可能来自供应商报告或估算，不等于最终账单。

遇到连接、凭证或工作区问题，先看工单错误和最后一段对话，再查[运维指南](RUNBOOK.md)。不要反复创建、重发或重启。

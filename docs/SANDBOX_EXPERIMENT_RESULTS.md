# 沙盒消融实验结果（2026-10-17）

本轮支持先保留最小沙盒 Shell，暂不增加强制 codemode、通用代理或 durable 层。观察到的主要收益是减少模型输入和估算费用；未观察到正确率或耗时改善。

## 条件

- 使用 `xhgj/gpt-6.1-sol`，thinking level 为 medium。八项生成样例，每组每项重复三次，共 72 次；三轮分别按 A/B/C、B/C/A、C/A/B 运行。
- A 为只读分页读取；B 为相同读取加独立容器 Shell；C 为 B 加可选的 SDK codemode，mode=on、models=false。
- 读取窗口 50 KiB ASCII 字符；所有组输入和精确 JSON 答案相同。每次新建内存 Pi session，B/C 每次新建容器。模型任务 180 秒，12 轮后请求中止，读取/Shell 预算 30 次；关闭自动 retry 和 compaction。
- 主实验运行于 2026-10-17 00:41:28 至 00:53:15（Asia/Shanghai）。执行方式和边界见[实验说明](SANDBOX_EXPERIMENT.md)。

## 主结果

失败样本保留在分母中，没有用补跑替换。

| 组别 | 精确答案通过 | 平均耗时 | 耗时中位数 | 平均输入 token | 平均 SDK 估算费用/次 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A：只读读取 | 24/24 | 7.88 s | 6.94 s | 37,816 | $0.2277 |
| B：读取 + 沙盒 Shell | 24/24 | 10.76 s | 11.30 s | 23,511 | $0.0971 |
| C：B + 可选 codemode | 23/24 | 10.47 s | 10.24 s | 30,208 | $0.1367 |

输入 token 是每次请求的 input、cacheRead、cacheWrite 之和，再按任务求均值；包含重复上下文。费用按 SDK usage 中的价格估算，受缓存命中和配置价格影响，不等于最终账单。

B 相对 A，平均输入 token 减少 37.8%，平均估算费用降低 57.3%，平均耗时增加 2.88 秒。B 共发起 54 次 Shell 调用，有 4 次工具错误，最终答案均符合要求。Shell 能在容器内先汇总再返回结果，减少大文件进入模型上下文，但脚本编写和额外模型轮次也有成本。

C 共发起 50 次 Shell 调用，有 6 次工具错误，**24 次任务均未主动调用 codemode**。因此本轮评估的是“额外开放 codemode”对模型策略的影响，不能据此判断实际 codemode 批量编排的执行效率或安全性，也不能把 C 的失败归因于 codemode 执行。

唯一未通过的样本为第三轮 `cross-service-filter` 的 C 组。它发生一次 Shell 错误，最后未返回合法 JSON；主实验未保存该次工具错误文本和最终原文，无法进一步准确归因。保留原始失败后，对同一任务补做 A/B/C 各三次、共 9 次带失败诊断的重复实验，全部通过且没有工具错误，未复现该问题。补跑不混入以上 72 次结果，也不证明原失败已修复。后续运行会保存有界的工具错误和失败回答。

## 执行开销与隔离

主实验固定脚本基准：容器启动约 289 ms；10 次热执行中位数为 311 ms，p95 为 387 ms。宿主固定程序的中位数为 20 ms。宿主 Node 为 24.18.0，镜像 Node 为 26.7.0，版本不同；该对照表示整条执行路径的粗测开销，不能严格拆分为纯容器隔离成本。

执行器使用本地 Node 镜像，image ID 为 `a1b97d6761bf16f53e69dfbb124d934f7bb9f523564a402b0e5dfa88ac29f6a9`。网络关闭，根目录只读，非 root、移除 capabilities、启用 no-new-privileges 和默认 seccomp；内存 512 MiB、CPU 1、进程 64。唯一宿主挂载是生成样例的只读目录；工作区和临时目录分别使用 128 MiB、64 MiB tmpfs。

最终独立检查通过 16 项，覆盖宿主和其他工单 canary 不可见、无容器引擎 socket、无宿主变量注入、样例/根目录只读、工作区可写、权限和网络状态，以及预先取消、运行中取消、超时、输出超限后容器被移除。验证了内存/PID 限制的配置，未通过耗尽资源验证，也不构成内核逃逸防护证明。

## 采用范围

1. 大文件聚合、关联和临时复现可以继续评估最小沙盒 Shell；小文件优先直接读取，避免无必要的脚本和模型轮次。
2. 暂不强制所有工具经过 codemode，也不增加新的 RPC 代理层。若要验证 codemode 实际编排收益，应另设明确要求编排的组。
3. 本轮没有证明生产正确率提高。八个样例存在正确率接近上限的问题，且验收只检查最终 JSON，未检验生成补丁、成果文件或测试覆盖。后续应使用真实问题的脱敏回放，并加入必须产生可验证成果的任务。
4. 当前容器只有 Node 和 Unix 工具，无网络、Python 和依赖安装；未接入真实 DMS/SLS、代码 worktree、工单权限或会话恢复。正式接入和 durable 迁移仍需独立验证。

本次未修改线上工单状态或权限，未重启服务。类型检查、200 项后端测试、100 项前端测试、构建和生产依赖审计通过。

## Responsibilities and scope

[engine.ts](../../src/agent/engine.ts) owns durable admission, per-Issue serialization, execution slots and reservations. Pi owns the model/tool pipeline, MCP discovery, connections and shutdown. Application identity, target authorization and budgets cannot be delegated to prompts or read-only hints.

[pi-session.ts](../../src/agent/pi-session.ts) returns one managed session with a live streaming accessor. Its single stop lifecycle disposes the SDK session before releasing command wrappers and the keyed runtime, attempts all cleanup stages and retains combined failures. Startup failure releases the resources it acquired through the same runtime cleanup owner.

Prod/test analysis keeps its environment's code/evidence scope. Dev code belongs to dev; evidence queries explicitly select prod/test. Included services expand allowed service/deployment tools; related Issues only add read-only evidence.

The system prompt guides diagnosis with available Issue evidence, recorded baseline branches and commits, cross-source checks and explicit evidence gaps. Work-mode playbooks require a causal chain from the reported entry point, competing hypotheses, a change impact checklist for code changes and explicit separation of verified, inferred and unchecked statements. Investigation alone does not authorize changes. Replies default to Simplified Chinese unless the user asks otherwise. The verification policy is a ladder: static reading first, dependency-free syntax checks (node --check, python3 -m py_compile, javac) when they apply, project type checking only with dependencies already present in the workspace or the Issue caches, and targeted tests when requested or needed for parsing, concurrency, transactions or edge cases; the Agent must report which checks it ran.

[prompts.ts](../../src/agent/prompts.ts) receives the environment kind, the Issue work mode and whether the session has service MCP configurations alongside the session context. Environment-dependent lines (query source environments, repository writability, development review, coding guidelines) follow the environment kind, the same fact that exposes workspace commit/push and query sources, not the current repository list. [playbooks.ts](../../src/agent/playbooks.ts) owns how to investigate, diagnose and change code: one shared problem-solving method plus one entry per work mode (production/test analysis, defect fix, feature development), selected from the stored environment/type pair. An unmapped pair gets the read-only fallback. Adding a work mode adds one playbook entry; permissions stay in prompts.ts and tool validation. The mcp__ line appears only when deployment-bound MCP connections of the entry or included services are configured; global connections never become Agent tools. Each rule has one owner: DMS pacing/backoff and inline-result handling are service_query tool guidelines; the no-routine-build policy is a single system-prompt line.

A request for SQL authorizes a draft, not execution. Even in read-only investigations, provide the requested data-changing statements for human review using verified tables, keys and predicates. Drafts omit variables, temporary tables and explicit transactions; deliver multi-step statements in dependency order rather than withholding them for lack of atomicity. For SQL-only requests, use SQL comments for any necessary preconditions. Tool permissions do not change.

## Admission and recovery

HTTP 201/202 does not mean model completion. Persist input and bind the session inside the per-Issue scope; preparation failures must not lose admitted messages. Pin the request sender and reauthorize after steering/session waits without switching identity.

A code-writable (dev) Issue may only be started by the developer role: the message and retry routes check the actor before heavy work and the engine's reauthorize callback rechecks the reloaded person against the Issue's current environment kind ([canWriteIssueCode](../../src/domain/contracts.ts), 403 developer_role_required). isAdmin is independent and does not grant it. Metadata and relation edits by other roles still save but do not start a dev round. Analysis Issues keep accepting every role. Inbound MCP `issue_message` posts to the same HTTP route.

Running-session input is durably admitted with a conservative started marker before steering. A sole undelivered steer can return to queued only after Pi removes it; the same entry is reused, never appended as another message. If the session was replaced before Pi received the steer, the admitted input is re-queued under its original entry ID; that is distinct from agent_message_outcome_unknown, which applies once Pi may have acted. Request IDs and sender identity live in this admission entry, not a second delivery database. Receipt lookup and sends share the per-Issue admission queue. Receipt reads hold off session mutations and shutdown without reporting Agent activity. Earlier pending inputs cannot be bypassed. A round that picks an older pending message releases its scheduling claim so the newly admitted input still gets a subsequent round. Pi refuses extension commands in steer, so `/` input during streaming is queued for the next round instead. Queued work must not use a disposed or replaced instance.

[message-delivery.ts](../../src/agent/message-delivery.ts) owns durable delivery metadata:

| Record | Recovery meaning |
| --- | --- |
| issue-pilot-user | Visible input and recorded scope |
| delivery started | May have been delivered; not completion; never automatically inject again |
| delivery rejected | Cancelled/scope changed; not automatically recovered |
| queued without started/rejected | Recover in order when the user explicitly continues |
| no queue metadata | Do not infer pending work |

agent_message_outcome_unknown is not permission to resend. Never replay an old session or overwrite newer state. Restart does not reconstruct the in-memory execution queue or automatically run unfinished rounds. Verify [message-admission.test.ts](../../tests/agent/message-admission.test.ts) and [engine.test.ts](../../tests/agent/engine.test.ts).

## Cancellation

Abort reauthorizes, marks current/queued rounds cancelled, drains input admission and waits for Pi abort/cleanup. Repeated aborts share the operation; conflicting reservations/new work are rejected while cleanup is active.

Cancellation retains reusable dev sessions and admitted input; read-only (prod/test) and scope-changed sessions retire as they would after a completed round. Cancelling during preparation stops the round signal: Git commands prepared by [WorktreeManager](../../src/workspace/git.ts) terminate with their process group and fail-fast checks skip remaining repositories, while compensation for created or removed worktrees uses independent, bounded Git operations. An explicit Git rollback failure marks the Workspace failed and rejects the pending cancellation, rather than reporting a clean stop. Attachment hash verification also checks the signal. The round then releases the personal SSH environment and checkout lease. It does not roll back completed file or remote effects, and cancelled input is not automatically restored by retry. Preserve state/diagnostics on failure instead of marking success. Model idle timeout measures continuous absence of model updates, resets on updates and pauses during tools; it is not a round deadline.

Owners: [engine.ts](../../src/agent/engine.ts), [pi-session.ts](../../src/agent/pi-session.ts). Regression: [cancellation.test.ts](../../tests/agent/cancellation.test.ts). Web Esc only initiates cancellation; it is not authorization.

## Reset, integrity and shutdown

Independent reset requires an active developer, an idle unresolved Issue and matching expectedSessionId. Close the old instance, create a new file and transactionally change its binding. Keep the old JSONL, set status=open and do not auto-run. After an uncertain response, read the current session rather than retrying with a fresh ID. Reset verifies only the expected identity from the old file's header/summary, not its full transcript: a final record cut off by ENOSPC/OOM/SIGKILL must not make reset unrecoverable. The old file stays byte-for-byte as evidence; history lists it with incomplete=true and reads of it still fail. Receipt lookup reads intact records from a cut-off archived transcript without opening it through Pi. Complete admission records deduplicate retries; a damaged interior is refused, and an explicit lookup with no matching receipt reports the incomplete history. A new admission may follow a cut-off tail because dispatch follows a synced admission and started marker.

Combined editing prepares the new session then commits metadata, attachment records, CC recipients and session binding in one SQLite transaction. Rollback removes only the prepared session; the old JSONL remains unchanged. Attachment files still use their own prepare/rollback/finalize owner. Owners: [session-reset.ts](../../src/agent/session-reset.ts), [issue-routes.ts](../../src/http/issue-routes.ts). Regression: [session-reset.test.ts](../../tests/http/session-reset.test.ts).

New session files, including the reset link, are fsynced with their directory before the FULL-sync SQLite binding commits; otherwise power loss can bind a truncated transcript. Only creation/reset sync the directory. Admission and transitions to started sync the existing file before acknowledgement or dispatch.

Before reading a bound session validate a nonempty regular JSONL, valid header/records and final newline. Never repair blanks, malformed lines or truncation automatically. SSE may skip missing durable replay; MCP follows its failure contract. Neither creates a replacement empty file. SDK reading of a complete old format may migrate it, so do not promise that every read is byte-preserving. Verify [session-read-integrity.test.ts](../../tests/http/session-read-integrity.test.ts).

The binding must name a private `.session-` file directly under its own Issue root. Summary and transcript validation share `openRegularSessionFile` in [pi-session.ts](../../src/agent/pi-session.ts): refuse special files without blocking on a FIFO and check the opened descriptor's path to reject symlinks in the parent directories as well as at the file. Reset writes its link as the first entry after the header; summary listing stops at that first entry and never follows later reset-shaped conversation records. This avoids scanning large tool outputs merely to list sessions. Full validation samples and parses through one descriptor; its bounded append cache changes only after successful validation, so a rejected session-ID rewrite remains rejected on retry while cached. This cache is an optimization, not a durable identity ledger or protection against every concurrent external rewrite; Pi subsequently opens the validated path.

Read-only rounds close instances at completion or cancellation and restore from durable history next round; idle dev instances may be reused. The application defaults Pi cache warming to streaming; warming between rounds requires explicit configuration. Failure cleanup stays serialized and cannot overwrite a newer round. Aggregate abort/shutdown/dispose and storage cleanup errors. Follow-up messages received during these rounds are persisted and queued for the next round; they never enter Pi's transient steering queue.

## Conversation Git

Native tools and stdio MCP can read the current Issue's Git metadata and inspect other authorized refs that are already available locally. They cannot change refs, HEAD or the index. Development uses the [workspace tool](../../src/agent/workspace-tool.ts) to stage named paths, unstage, commit staged changes, or push the recorded branch to the same name on origin. `sync` fetches that exact remote branch into the private store and fast-forwards only a clean worktree. For ahead/diverged/dirty results it reports both tips, counts and bounded per-side commit IDs. A failed fetch cannot use a stale tracking ref. Explicit `merge` re-fetches and checks the reviewed local/remote tips, starting a two-parent merge without committing. Unresolved paths or a resolved index awaiting commit remain in Git, not SQLite. Repeated sync/merge reports the pending state; do not push or release until the merge is completed. Stage reviewed resolutions, commit and push only with authorization; ambiguous conflicts require the user's decision. Neither operation rebases, resets, auto-stashes or force pushes. Each operation rechecks the recorded private store and both worktree links. Fixed Git commands use SRT with writes to that store only; only the fixed network commands (same-branch fetch and push) receive the selected developer's personal SSH key, never the merge or a shell tool. Application Git invocations outside the sandbox are hardened against repository configuration and never recurse into submodules; a newly staged embedded repository is refused (see [Storage](STORAGE.md#git-and-workspaces)). There is no force push, branch creation or switching, or publication to another ref. Test and production conflict resolution belongs to the corresponding integration or merge request; environment-specific changes stay out of the Issue branch.

Development review is owned by [prompts.ts](../../src/agent/prompts.ts) and injected only for code-writable environment kinds (canModifyIssueCode). The vendored [Karpathy coding guidelines](../../src/agent/karpathy-guidelines.ts) follow the same condition, after an explicit statement that the project verification policy takes precedence. After implementation, the Agent reviews the Issue diff including staged/unstaged changes and new files, follows callers and trust boundaries, fixes confirmed in-scope defects when authorized, and reruns relevant checks. Findings identify evidence, trigger, impact, severity and minimum remedy. Unresolved findings are reported, not a commit/push approval gate; a later explicit user instruction can proceed with the stated risk. Existing task-specific verification budgets still apply.

Explicit user authorization remains necessary for commit/push. Before commit, review the exact staged content against HEAD. Before push, review all commits from the recorded Issue baseline to the bound branch tip, including earlier commits and their intermediate changes, then confirm the tip still matches. Initial/continuation repository context and workspace scope-change results expose that baseline from the existing preparation/commitBefore record. This covers the Issue's commits even before its first push, when no remote-tracking ref exists; it does not claim to verify the live remote. An unavailable baseline or one that is not an ancestor blocks the push rather than prompting a guessed comparison. Changes after review require re-review of affected content; unchanged reviews may be reused. Record the scope, baseline/tip, findings, actual verification and remaining limitations in the Issue conversation. This is a prompt workflow, not an enforced Git approval gate; it adds no review state machine or claim of independent/human approval. The review approach draws on [Vercel's code-review guidance](https://github.com/vercel-labs/open-agents/blob/main/.agents/skills/code-review/SKILL.md); no additional skill installation is required.

## Native evidence queries

[service-query-tool.ts](../../src/agent/service-query-tool.ts) parses unknown boundary input and dispatches environment/service/capability to its owner. Targets come from authorized deployments, not credentials. Keep execution checks required after mutable Pi hooks.

Inline results enter model context, so the pretty-printed JSON returned to the model is bounded by root `limits.capability.inlineResultBytes` (128 KiB). Exceeding it is an explicit failure, not truncation: SLS returns `sls_result_too_large_narrow_query` (narrow the window, add filters or use SQL with LIMIT) and DMS returns `dms_mcp_result_too_large_use_export` (add LIMIT/filters or export). The 1 MiB `resultBytes` remains the SLS CLI per-page stdout, MCP and DingTalk budget and the saved-evidence read budget, so results persisted under the earlier budget stay readable. DMS export writes the complete response as a work file without the inline budget.

### DMS

Use HTTPS SSE MCP with the selected owner's complete personal or shared group. Accept configured instanceAlias/schema intent, never model-supplied arbitrary hosts/databaseIds.

Before connecting, enforce the root `limits.capability.dms.scriptChars` script budget (64 KiB, also the tool schema maxLength) and read-only SQL checks against writes, multiple statements, comments, locks and known side effects. The keyword check runs on unquoted text, so the script description tells the model to backtick-quote identifiers such as `do`, `load`, `lock`, `release` or `handler`. These checks are not a proof for every SQL extension; the remote account must itself be read-only.

Root defaults are 120 seconds per execution and 12 seconds for first handshake. At most two handshakes: only first-handshake timeout or bounded Retry-After 429 permits retry; never retry 401/403. Backoff and retry share the budget. Discovery/execution failure does not reconnect/replay; dispatched SQL is not automatically queried again.

One DmsQueryRound owns connections and tool discovery for one Agent prompt, keyed by the exact selected URL/Authorization. Queries serialize within that round and include queue wait in their timeout; no connection crosses Issues, credentials or rounds. The handshake borrows the request deadline, but an established transport belongs to the round lifetime. A failed call invalidates its connection without SQL replay. Successful evidence/export returns before round disposal; disposal failure is reported separately at round completion. Standalone queries retain per-call ownership. Diagnostics retain phase, elapsedMs, sqlDispatchAttempted and retryAfterSeconds without secrets. Preserve operation and close failures together; cleanup failure is not ordinary cancellation.

Diagnostic codes come from DomainError owners, without a second message whitelist. Private details and raw SDK errors stay in the cause chain, never in Agent diagnostics. Exports use ordinary work files and replace only after content/protocol success; preserve prior files on failure. Owner: [dms.ts](../../src/capabilities/dms.ts); regression: [dms.test.ts](../../tests/capabilities/dms.test.ts).

### SLS

Use aliyun sls GetLogsV2. Authorize exact region/project/logstore, even when configuration permits a wildcard. When a scope lists targets, execution uses only targets; configuration writes require the top-level region/project/logstores to equal targets[0] (sls_scope_targets_mismatch otherwise). Stored rows are not reparsed on read. CLI uses 0600 temporary credentials, HTTPS and disabled automatic retries; never mutate the host profile or place keys in argv.

The tool schema states that from/to are Unix epoch seconds, that omitting both reads only the last `defaultWindowSeconds` (15 minutes; `traceWindowSeconds`, 24 hours, with trace_id), and that trace_id accepts only UUID format, is mutually exclusive with query, and other trace ID formats are searched through query. An empty result covers only the queried window.

Accept only Complete. Page ordinary logs by offset; SQL analysis retains its query limits and returns its analysis result page. A later-page failure, budget failure or incomplete result is not successful partial evidence; paging stops once accumulated records exceed the inline budget. Return source and time.

Cancellation/timeout terminates the process group and cleans credentials. The CLI owner declares safe query failures as DomainError; callers preserve that classification without a second code catalog. Do not expose arbitrary CLI error text. One finally path removes credentials exactly once, retaining query and cleanup failures together; cleanup failure is internal and is not downgraded to cancellation. Owners: [sls.ts](../../src/capabilities/sls.ts), [sls-cli.ts](../../src/capabilities/sls-cli.ts); tests: [sls.test.ts](../../tests/capabilities/sls.test.ts), [CLI fixture](../../tests/integration/sls-cli.acceptance.ts).

### MCP and Codemode

Inbound /mcp operates Issues; service MCP provides deployment tools; global connections (no deployment_id) serve DingTalk imports only, and deployment-bound rows are service tools regardless of name. Do not combine their authority. MySQL uses configured external MCP; retired adapters do not execute.

DMS/SLS can run through Codemode tools.service_query. off exposes direct tools, on combines direct/orchestrated use, only primarily uses orchestration discovery. The SDK alone owns process-wide FIFO worker admission, cancellation and release after actual worker exit. Pi 1.5.2 defaults to two workers; a positive PI_CODEMODE_MAX_WORKERS overrides capacity. Waiting is capped at 60 seconds and counts toward any shorter script deadline; this is not the query execution budget. When a script omits `timeout_ms`, the application applies a 5-minute deadline, including when only `max_output_tokens` is set. Explicit deadlines and output budgets are preserved. A preflight refuses a missing package for which Pi would request installation (`agent_package_source_missing`); Pi offline mode may skip unavailable packages. Keep Operator package installations stable while sessions are starting. The application adds no second queue or waiter-count limit. Cancelled or timed-out waiters do not execute; script parallelism does not bypass Issue/repository/DMS constraints.

Pi owns registration, discovery, connection, cancellation and shutdown. The application retains same-origin/redirect checks, SQLite authority, literal credentials, budgets and authorization. See [client.ts](../../src/mcp/client.ts), [pi-extension.ts](../../src/mcp/pi-extension.ts), [codemode-extension.ts](../../src/agent/codemode-extension.ts) and [patches](../../patches/README.md).

## Files, host tools and resources

The Issue root is the only persistently writable model directory; related Issues are read-only. Local tools can read only the validated shared snapshots and required Git storage for the current and explicitly related Issues. A successful workspace include/remove updates the native tool read roots immediately; a failed preparation reverts only membership changed by that invocation (retrying an existing include does not remove it), keeps runtimeReady false and still retires the live session, while stdio connections retain their launch policy until the session is retired. Releasing, reopening, converting or migrating the scope of an Issue marks live sessions of Issues that read its evidence as scope-changed so their next round re-prepares related roots, without reserving those readers. Preparation reads attachment originals without automatic editable copies; explicit edits create ordinary work files. Pasted images belong to Pi messages. Query exports and SDK large outputs use ordinary files; no second publication/snapshot layer.

Node/npm, Java/Maven and Python use host PATH/shared libraries. Do not inject a project .venv or create an Issue environment by default. Host tools are read-only; administrators install shared dependencies. Project dependencies and writable .npm-cache/.maven-cache remain Issue-local. [network-exec.ts](../../src/agent/network-exec.ts) redirects Java temporary files and caches to the Issue. Use normal programs/libraries for formats, not format-specific executors, nested sandboxes or selectable runtime frameworks.

Pi resources use the runtime user's getAgentDir(). No application-private skills/extensions or Issue-local extensions. Inspection discovers without executing extensions; Operator extensions cannot override protected application tools. Owners: [pi-runtime.ts](../../src/configuration/pi-runtime.ts), [pi-session.ts](../../src/agent/pi-session.ts).

## Conversation and cost projection

[events.ts](../../src/agent/events.ts) projects the current active branch, hiding internal context-edit/usage entries while footer accounting includes applicable usage. [usage.ts](../../src/agent/usage.ts) owns cumulative token/cost merging and the valid-assistant-context rule for both the server snapshot and live Web events. SDK nested-call records must not be interpreted as success when incomplete.

[event-display.ts](../../src/agent/event-display.ts) bounds tool text at the root-configured 40,000 characters before HTTP serialization and as a Web fallback, including SDK message-start/end and turn/agent-end copies. The Web projection omits SDK-only `structuredContent` duplicates. Keep head/tail and displayTruncated; do not mutate JSONL or model results. Images, details, nestedCalls and total history are not bounded by this text rule. SSE/history use the same projection.

[query-results.ts](../../src/agent/query-results.ts) retains successful native inline `service_query` evidence. Direct calls reuse SDK tool messages; after `turn_end` their persisted entry IDs are published. Nested calls append one `issue-pilot-query-result` custom entry to the existing session JSONL after mutable hooks and before returning to the script. These entries never enter model context and do not duplicate `structuredContent`. A persistence failure fails/aborts the round even if the script catches its tool error. Exports and unrelated/failed tool outputs are excluded. Previously unrecorded nested results cannot be reconstructed.

Live and replay use the same completion projection with an exact session/entry reference. [QueryResult.tsx](../../src/web/src/app/QueryResult.tsx) explicitly reads truncated results through the validated session/reset chain; no query rerun, result index or publication file is created. Reads restrict entries to the displayed branch and retain the native 1 MiB UTF-8 result budget. Expansion owns the loaded body; collapse, identity/result changes and disposal cancel reads and reject late responses. Reads still open the session through its existing owner, so response size does not bound total session-read memory.

Complete `aliyun-sls-cli` results use a local table with source/time metadata and an original text view. Filtering and 50-row pagination never dispatch queries. Failed, unrecognized or wider-than-32-column results stay as text. DMS's [upstream executeScript wrapper](https://github.com/aliyun/alibabacloud-dms-mcp-server/blob/f8e1ae32a52ad77d01ff8bd4b5e657b653196906/src/alibabacloud_dms_mcp_server/server.py#L779) returns Markdown, not its internal typed rows. Render its MCP text using the existing sanitized Markdown component without the Markdown cache, retain raw response/source metadata, and do not infer types or reconstruct rows. Above the display character budget, complete DMS responses remain plain text to bound Markdown table mounting. No SDK display-string scraping or speculative protocol variants.

Table sorting derives from retained rows without mutating source order; numeric columns sort numerically and missing/null values stay last. Copying filtered results includes every matching page in the visible sort order and preserves JSON types. Row details use the shared native dialog and show complete values; only table previews are shortened. A changed result invalidates its open details and copy notice, and unmount rejects late clipboard feedback. Tool timing changes preserve result identity. Clipboard fallback targets must stay inside the active native dialog, because its background is inert. Dialog Escape never invokes the Agent's interrupt shortcut, including events propagated through a Portal.

Cost preserves SDK usage and provider/estimated/unknown provenance. Reconnect replaces totals rather than adding replay; failure/cancellation retain reported charges. Web draft lifetime is described in [Usage](../USAGE.md#阅读与补充).

## Execution boundary

[issue-sandbox.ts](../../src/agent/issue-sandbox.ts) owns the single SRT boundary. Linux namespaces, seccomp and a read-only host view constrain local operations. Only the current Issue root is persistently writable. Protect Git config/hooks/pointers, reject cross-boundary hardlinks and retain launch-environment checks. The hardlink check streams `find` output and stops at root `limits.process.hardlinkEntries` (200000) entries, failing with issue_hardlink_entry_limit_exceeded; it is not a byte budget.

Reads are deny-by-default over the host home directory, not read-everything-minus-a-denylist: [issueReadPolicy](../../src/agent/issue-sandbox.ts) denies `os.homedir()` and the account home (SRT mounts a tmpfs there) and re-allows only what Issue tools need — the Issue root, the application directory, Pi agent `bin`/`skills`/`npm`/`git` (fd/rg and skill files, not `settings.json`, `models.json`, `auth.json`, `mcp-auth.json`, `sessions` or editor swaps), `~/.local/bin` and `~/.local/lib` (pip user site with openpyxl, global npm prefix), `~/.agents/skills`, explicitly related Issues, the temporary personal SSH directory only for the workspace fetch/push invocations, and the proxy sockets. Bash and stdio MCP do not receive that directory, and it is not a general readable path. Everything else under home (checkpoint database copies, application logs and release evidence, `~/.ssh`, `~/.git-credentials`, `~/.gitconfig`, `~/.npmrc`, `~/.config`, `~/.codex`, `~/.claude*`, `~/.cache`, `~/.local/state`) stays hidden, as do `os.tmpdir()` and the state root. Maven/npm caches remain Issue-local, so no `~/.m2` allowance exists. Regression: [sandbox-read-policy.test.ts](../../tests/agent/sandbox-read-policy.test.ts).

SRT's mandatory deny scan starts from the application checkout (process.cwd), not the Issue root. At prepare time the application therefore explicitly denies creation as well as writes to dangerous configuration names inside the writable Issue root (`.bashrc`, `.gitconfig`, `.mcp.json`, `.vscode`, `.idea`, `.claude/{commands,agents}` and the like) and to each top-level repository's `.git`. If `/tmp/claude` or `/private/tmp/claude` exists, sandbox creation is refused with issue_sandbox_shared_temp_exists because SRT rebinds its own write path there and its contents would be visible to every Issue.

Network uses proxy/proxychains. open/allowlist does not grant arbitrary local file or website authority; see [network policy](CONFIGURATION.md#issue-network-access). In open mode, IPv6 literals carrying IPv4 (NAT64 `64:ff9b::/96`, 6to4 `2002::/16`, IPv4-translated `::ffff:0:0:0/96` and IPv4-compatible `::/96`) have the embedded address unpacked before the same loopback, link-local and cloud-metadata refusals apply. The temporary personal SSH directory is passed only to the workspace fetch/push invocations, not to bash or stdio MCP.

Pi SDK, Operator extensions and application owners are trusted code. Remote MCP has independent authority. Never present local isolation, prompts or readOnlyHint as remote database authorization.

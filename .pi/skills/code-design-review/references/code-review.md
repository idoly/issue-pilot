# Code Review Reference

本文件补充 `SKILL.md`，按 `SKILL.md` 第五节的触发条件按需读取；冲突时以 `SKILL.md` 为准。

## 一、裁决原则

1. **质量优先**：正确性、安全性、数据一致性及明确的性能、可用性要求优先。
2. **兼容与完整**：保障必要兼容性，确保关联变更完整。
3. **简单与内聚**：在满足质量要求后，选择认知和维护成本更低的方案。
4. **合理扩展**：仅针对真实变化点引入有收益的抽象。
5. **风险匹配**：验证与治理流程应与任务风险相匹配。

## 二、消融检查

对新增复杂度进行必要性判断：

| 检查对象 | 判断问题 |
|---|---|
| 新增代码 | 是否可以复用、合并或删除？ |
| 接口与抽象 | 是否隔离了真实变化或职责？ |
| 模块拆分 | 是否提高内聚，还是增加跳转成本？ |
| 配置选项 | 是否存在实际使用场景？ |
| 新增依赖 | 现有能力是否足够？ |
| 防御逻辑 | 是否保护真实边界，还是掩盖错误？ |
| 兼容逻辑 | 是否存在明确的兼容要求？ |

可以通过静态分析、方案对比或实际验证完成，不要求每次开展独立实验。

## 三、影响范围发现

根据变更类型和风险，按需检查：

- **静态引用**：符号、字符串、配置键、路由及事件名。
- **依赖关系**：调用方、模块、包及构建依赖。
- **动态机制**：反射、插件加载、依赖注入及序列化注册。
- **测试与契约**：相关测试覆盖、接口契约及兼容性。
- **运行与部署**：迁移脚本、环境配置、构建产物及部署流程。

无法确认关键影响时先说明风险，不擅自扩大修改范围。

## 四、最小验证矩阵

| 任务类型 | 验证重点 |
|---|---|
| 新功能 | 验收标准、主要路径、边界条件 |
| Bug 修复 | 问题复现、修复有效性、回归测试 |
| 重构与简化 | 变更前后行为及契约一致 |
| 接口变更 | 调用方、请求响应、错误处理及兼容性 |
| 依赖变更 | 依赖解析、构建、测试、运行时加载 |
| 配置变更 | 启动、关键路径、环境差异及恢复方式 |
| 数据迁移 | 数据一致性、执行顺序、回滚或恢复方案 |
| 冗余清理 | 静态与动态引用、构建、插件及部署影响 |
| 性能优化 | 基准数据、优化收益、功能回归 |

验证结果：

- **已验证**：实际执行，说明检查内容及结果。
- **未验证**：说明未执行原因、风险及建议的验证方式。
- **验证失败**：说明失败现象、影响及已知原因。

静态检查、构建成功和运行验证不得相互冒充。不要求执行与变更无关的全面测试。

## 五、依赖与冗余治理

- 检查未使用、重复、过时或功能重叠的依赖。
- 评估移除、合并及替换的收益与兼容成本。
- 检查废弃代码、文件、目录、配置、构建脚本及插件。
- 删除前核实静态引用、动态加载、反射、迁移脚本及部署影响。
- 本次变更产生的冗余应在授权范围内同步清理。
- 无关历史问题仅报告；安全性无法确认或超出授权范围时，先请求确认。

目标是降低整体维护成本，而不是追求最少代码行数、文件数或依赖数量。

## 六、例外处理

允许有充分理由的例外。重要或高风险例外应记录：

| 字段 | 内容 |
|---|---|
| 事项 | 偏离的规则 |
| 原因 | 必要性与依据 |
| 影响 | 涉及范围及风险 |
| 验证 | 已执行检查及结果 |
| 后续 | 是否需要治理及责任人 |
| 授权 | 项目负责人或授权维护者 |

低风险任务不强制填写模板。

## 七、案例沉淀

仅记录具有复用价值的真实案例，包括背景、方案、结论、收益、成本及参考代码。

不为建立案例库而增加无价值文档。

**最终判断：必要性、简洁性、内聚性、最小性、可验证性。**
